# Plan

The approved strategy for the *current* piece of work only. Empty/generic between tasks
— a fresh session should fill this in once a plan is actually agreed with the user, and
clear it back out (or overwrite it) once that work ships.

## How to use this file

- When the user approves an approach for a non-trivial task, write it here as the actual
  steps (not just "implement X") — this is what a session resuming after compaction
  should read to know *how*, not just *what*.
- One plan at a time. Don't accumulate a backlog of future plans here — that's
  tasks.md's job.
- Overwrite this section when the plan changes; don't keep stale alternatives around.
